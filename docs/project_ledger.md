- Spike 3b (live, 2026-09-29, one run, [DL-013](decision_log.md#dl-013--spike-3b-result-a-catch-all-listener-hears-lua-crash-text-including-crashes-in-event-and-bind-handlers)): a catch-all listener hears a Lua crash as one chat line (message, `stack traceback:` and frames, line breaks removed) for a crash in the main chunk, an `mq.event` handler and an `mq.bind` handler. Handler crashes do not stop the script and do not change `Status` or the exit line; only the error text shows them.
- Spike 4 (local, 2026-09-29, [DL-015](decision_log.md#dl-015--spike-4-result-the-mcp-python-sdk-installs-and-works-on-python-314)): Python is 3.14.7 64-bit; `pip install mcp` gave 2.2.0 with no broken requirements, and a stdio server/client round trip worked. `mcp` 2.x renamed `FastMCP` to `MCPServer`. Not tested under Claude Code's `.mcp.json` launch.
- Spike 5 (live, 2026-09-29, one run, [DL-016](decision_log.md#dl-016--spike-5-result-a-fake-tell-fires-mqevent-so-autoinvs-tell-path-is-testable-with-one-character)): an `/echo` of a fake tell, typed-style or sent by a script with `mq.cmd` or `print()`, fires an `mq.event` using autoinv's own tell pattern with sender and body captured exactly (spaces kept), and the group-leave pattern fires the same way. autoinv's tell tests can run in Phase 1 with one character. A real tell from another player was not tested (Phase 2).
- Spike 6a (live, 2026-09-29, one run, [DL-019](decision_log.md#dl-019--spike-6a-result-mqparse-silently-truncates-its-output-at-2047-bytes)): `mq.parse` silently truncates its result to 2047 bytes (no error, no console message). A true 2047-byte value looks the same as a truncated one. Input-side behavior (test 6b) is not yet tested.
- Spike 6b (live, 2026-09-29, one run, [DL-020](decision_log.md#dl-020--spike-6b-result-a-2048-byte-input-to-mqparse-crashes-the-client)): `mq.parse` inputs of 2000, 2046 and 2047 bytes worked; an input of exactly 2048 bytes crashed the whole EverQuest client instantly (the log's last line is the "about to parse" line for 2048). 2049 and 3000 were not run. Cause is likely the fixed 2048-byte buffer copy but not confirmed. Any path that lets an expression of 2048 bytes or more reach `mq.parse` can kill the game.
- Spike 7 (local, 2026-09-29, DL-021 evidence note): with `mcp` 2.2.0, a tool that raises an ordinary exception reaches the client as the generic text "Error executing tool <name>" (the message is hidden), while a tool returning an explicit `CallToolResult(is_error=True, ..., structured_content={...})` delivers both text and structured data. Tools therefore return explicit error results carrying `kind` in the text and in `structured_content`. Whether Claude Code shows the model the structured data is not verified.
- `rxi/json.lua` 0.1.2 (read and tested 2026-09-29, DL-021 evidence notes, standalone LuaJIT): escapes control bytes but passes bytes 0x7f and above raw and unvalidated; a `nil` object field disappears and a decoded `null` becomes a missing key; decode errors embed the offending input; decode time is roughly quadratic for strings with many escapes (a 32 KiB file decodes in about 0.03 to 0.05 s at worst; 160 KB with 80,000 escapes took about 1 s); nesting deeper than roughly 8,000 to 16,000 levels fails with a catchable `stack overflow` in about a millisecond. Adopted unmodified (design item 13).
- Spike 8 (live, 2026-09-29, 32-bit client, [DL-021](decision_log.md#dl-021--phase-1-slice-1-design) evidence notes): `require('ffi')` works in MacroQuest's Lua and `ffi.arch` is `x86`. `os.rename` onto an existing file fails (`File exists`), and `os.remove` of a held-open file fails (`Permission denied`). `MoveFileExA` with `MOVEFILE_REPLACE_EXISTING` replaces a missing or unheld destination and fails safely (`GetLastError 5`, destination unchanged) when a reader holds the destination open; `GetLastError` is authoritative and `ffi.errno()` gave a stale value. No crash.
- Spike 9 (live, 2026-09-29, one run, DL-021 evidence note): a tight-loop Python reader made 185,008 reads of a test heartbeat file that the bridge-style writer replaced 6,002 times through `MoveFileExA`: 182,383 exact matches of a published generation; zero missing, invalid UTF-8, invalid JSON, inconsistent or backwards reads; 2,625 transient `PermissionError` open failures counted separately; the writer's replace was refused 3,935 times (`GetLastError 5`) under this extreme contention. Empirical evidence, not a Windows guarantee; ASCII paths only. Basis of the approved heartbeat mechanism (design item 26).
- Spike 10 (live, 2026-09-29, one 180 s run of four zone changes, DL-021 evidence notes): the largest contiguous gap in Lua execution was 9,255 ms entering The Overthere (heavy, not visited for a month); the lighter or frequently visited transitions (an empty Bazaar instance, the Bazaar with 166 players, a private Umbral Plains dynamic zone) each stalled about 3.9 to 4.3 s. After each big gap there were two further stalls of about 1.6 to 1.8 s, with the script executing between them, so they are not added to the big gap. Baseline cadence with no zoning: median 111 ms per 100 ms sample. `EverQuest.GameState` read `INGAME` throughout, including during every zone change, so it cannot detect zoning; a same-zone instance hop does not change the zone short name. Four transitions, not a worst-case bound.
- Installed MacroQuest origin (developer-confirmed 2026-09-29, from browser history and TAC's release notes): the [rel-emu-rof2 release](https://github.com/macroquest/macroquest/releases/tag/rel-emu-rof2). `references/MacroQuest Source` is that release's "Source code (zip)", unzipped by the developer (developer-confirmed), and its changelog matches the install's. Residual gap: not checked whether the release was re-published between install and source download.
- MacroQuest source review (2026-09-29, [DL-008](decision_log.md#dl-008--macroquest-source-review-print-routing-event-sources-and-logging)): Lua `print()` calls `WriteChatColorf`, which runs every plugin's `OnWriteChatColor`; the Lua plugin's handler feeds the line to every running, unpaused script's event processor. Nothing on that path writes a file. Lua errors are also written through `WriteChatColorf` (red). Output is dropped for events while `gFilterMQ` is set (`/squelch`, `/filter mq`).
