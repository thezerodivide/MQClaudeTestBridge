## Resolved behavior

Behavior actually agreed upon (source: [SPEC.md](../SPEC.md), approved as current source of truth).

- Crash detection uses the error chat text heard by the bridge's catch-all listener; there is no wrapping runner in v1 ([DL-014](decision_log.md#dl-014--crash-detection-uses-the-error-text-the-runner-is-out-of-v1), supersedes the spec's earlier runner design). Revisit only if a real need turns up.

- Output capture is our Lua's job: MacroQuest writes no log of console or `print()` output, so the bridge, runner and `testlog` write what Claude needs to `events.jsonl` ([DL-009](decision_log.md#dl-009--output-capture-is-the-bridges-job-because-macroquest-writes-no-log)). EverQuest logs are read directly from disk.

- Two-part architecture: `claudebridge` (Lua, in MacroQuest, the only thing that touches the game) and `mq-mcp` (Python MCP server, turns bridge commands into Claude-callable tools). Claude never touches the game directly — every action goes through the MCP server and the shared folder to the bridge.
- Transport is files (an inbox/outbox folder, polled ~100ms), not sockets, for v1 — sockets are deferred to Phase 3 (multi-PC).
- A per-test command allowlist enforced in the bridge itself, not just in Claude's instructions — see [DL-003](decision_log.md#dl-003--guardrail-mechanisms-allowlist-kill-switch-watchdog-audit-log).
- Claude designs its own unhappy-path tests from reading the script under test, rather than only confirming the happy path; a standard checklist (window closed mid-run, malformed input, timeouts, repeated/spammed input, mid-run stop/restart/zone, resource exhaustion) applies to every script tested.
- Claude never fixes a bug in a script under test unprompted — it proposes testability hooks, gets approval before adding anything, and reports findings for the developer to act on. See [DL-001](decision_log.md#dl-001--retrofit-seeding-this-log-from-specmd-existing-decisions-made-section).
- Test character convention: fresh level 1, 2nd/3rd classes obtained, given platinum, moved to PoK. See [DL-004](decision_log.md#dl-004--test-character-convention).
- autoinv has exactly one gating switch (guild-only on/off); no group-only or whitelist-only mode. See [DL-005](decision_log.md#dl-005--autoinv-approval-semantics-code-is-authoritative-over-prior-descriptions).

- Spike 7 (local, 2026-09-29, DL-021 evidence note): with `mcp` 2.2.0, a tool that raises an ordinary exception reaches the client as the generic text "Error executing tool <name>" (the message is hidden), while a tool returning an explicit `CallToolResult(is_error=True, ..., structured_content={...})` delivers both text and structured data. Tools therefore return explicit error results carrying `kind` in the text and in `structured_content`. Whether Claude Code shows the model the structured data is not verified.
- `rxi/json.lua` 0.1.2 (read and tested 2026-09-29, DL-021 evidence notes, standalone LuaJIT): escapes control bytes but passes bytes 0x7f and above raw and unvalidated; a `nil` object field disappears and a decoded `null` becomes a missing key; decode errors embed the offending input; decode time is roughly quadratic for strings with many escapes (a 32 KiB file decodes in about 0.03 to 0.05 s at worst; 160 KB with 80,000 escapes took about 1 s); nesting deeper than roughly 8,000 to 16,000 levels fails with a catchable `stack overflow` in about a millisecond. Adopted unmodified (design item 13).

No crash.
- Spike 9 (live, 2026-09-29, one run, DL-021 evidence note): a tight-loop Python reader made 185,008 reads of a test heartbeat file that the bridge-style writer replaced 6,002 times through `MoveFileExA`: 182,383 exact matches of a published generation; zero missing, invalid UTF-8, invalid JSON, inconsistent or backwards reads; 2,625 transient `PermissionError` open failures counted separately; the writer's replace was refused 3,935 times (`GetLastError 5`) under this extreme contention. Empirical evidence, not a Windows guarantee; ASCII paths only. Basis of the approved heartbeat mechanism (design item 26).
- Spike 10 (live, 2026-09-29, one 180 s run of four zone changes, DL-021 evidence notes): the largest contiguous gap in Lua execution was 9,255 ms entering The Overthere (heavy, not visited for a month); the lighter or frequently visited transitions (an empty Bazaar instance, the Bazaar with 166 players, a private Umbral Plains dynamic zone) each stalled about 3.9 to 4.3 s. Baseline cadence with no zoning: median 111 ms per 100 ms sample. `EverQuest.GameState` read `INGAME` throughout, including during every zone change, so it cannot detect zoning; a same-zone instance hop does not change the zone short name. Four transitions, not a worst-case bound.
- Installed MacroQuest origin (developer-confirmed 2026-09-29, from browser history and TAC's release notes): the [rel-emu-rof2 release](https://github.com/macroquest/macroquest/releases/tag/rel-emu-rof2). `references/MacroQuest Source` is that release's "Source code (zip)", unzipped by the developer (developer-confirmed), and its changelog matches the install's.
